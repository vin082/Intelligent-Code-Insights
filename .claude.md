# Intelligent Code Insights - Claude Instructions

## Project Overview

**Intelligent Code Insights** is an AI-powered code intelligence platform that enables developers to query Java codebases using natural language. Built with Adaptive RAG architecture combining vector search (FAISS) with relationship-aware filtering.

**Tech Stack**: Python, Streamlit, LangGraph, OpenAI GPT-4o, FAISS

## Architecture

### Modular Structure
```
src/
├── config/       # Settings and configuration
├── models/       # Data models (GraphState)
├── services/     # Business logic (DocumentLoader, VectorStore, LLM)
├── utils/        # Utilities (Java parsing, filtering)
├── workflow/     # LangGraph nodes and routing
├── ui/           # Streamlit components
├── core/         # Initialization logic
└── app.py        # Main entry point
```

### Key Patterns
- **Service Layer**: All business logic in services/
- **Dependency Injection**: Services injected into workflow nodes
- **State Machine**: LangGraph manages workflow state
- **Separation of Concerns**: UI, logic, and data layers clearly separated

## Project-Specific Rules

### ⚠️ Important Constraints
1. **Never modify** `code_streamlit_app.py` (legacy monolithic file, keep for reference)
2. **All new code** goes in `src/` directory following modular structure
3. **Secrets management**: Keep API keys in `.env` file only
4. **Java test code**: Located in `java_code/` directory
5. **Documentation**: Keep `ARCHITECTURE_DIAGRAM.md` and design docs updated

### Configuration
- All settings centralized in `src/config/settings.py`
- Environment variables loaded via `python-dotenv`
- No hardcoded values in code

### LangGraph Workflow
- State schema defined in `src/models/state.py`
- Nodes defined in `src/workflow/nodes.py`
- Routing logic in `src/workflow/routing.py`
- Graph builder in `src/workflow/builder.py`

## Testing Approach

### When Adding Features
1. Test locally with sample Java code
2. Verify query quality node catches bad queries
3. Test relationship filtering with structural queries
4. Validate self-reflection catches hallucinations
5. Check UI displays process steps correctly

### Sample Test Queries
- **Semantic**: "How does payment processing work?"
- **Structural**: "What calls OrderService?"
- **Short**: "User" (should trigger rewrite)
- **Hallucination test**: "How does blockchain work?" (should fail gracefully)

## Common Tasks

### Adding a New Workflow Node
1. Define node function in `src/workflow/nodes.py`
2. Update routing logic in `src/workflow/routing.py` if conditional
3. Add to graph in `src/workflow/builder.py`
4. Update `GraphState` in `src/models/state.py` if needed
5. Test with UI to see intermediate steps

### Adding a New Service
1. Create service class in `src/services/`
2. Follow dependency injection pattern
3. Add to `__init__.py` exports
4. Import and inject in workflow nodes

### Updating UI Components
1. Modify components in `src/ui/components.py`
2. Update styles in `src/ui/styles.py` if needed
3. Keep UI logic separate from business logic

## Debugging Tips

### Enable Detailed Logging
Check "Show process steps" in UI sidebar to see:
- Query quality assessment
- Retrieval and filtering details
- Document grading scores
- Self-reflection results

### Common Issues
- **Slow queries**: Check VECTOR_STORE_K setting (lower = faster)
- **Poor answers**: Verify relevant code is indexed
- **Hallucinations**: Self-reflection should catch these (check intermediate steps)
- **Memory issues**: Increase chunk size or reduce codebase
